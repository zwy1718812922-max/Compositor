### 渲染与滤镜

`gpu-renderer.js` 从现有 `renderInto` 接入 WebGL2，合成表面以 512 像素块处理。纹理及帧缓冲使用预乘 sRGB；混合公式依据 [W3C Compositing and Blending](https://www.w3.org/TR/compositing-1/)，上下文及帧缓冲检查遵循 [WebGL 2.0](https://registry.khronos.org/webgl/specs/2.0.0/)。支持移动、缩放、透明度、纯色/线性渐变、正常/正片叠底/滤色/叠加/变暗/变亮/差值/强光/柔光/排除。亮度、曲线、色相及其余 16 类已有调整复用 `fill-model.mjs` 的参数与计算语义。

源纹理按可见范围缓存，1024 像素块带采样边缘；符合现有相位和尺寸网格的缩小采用缓存层级。非对齐的缩小、文字、旋转、FX、蒙版先用原 Canvas 采样规则生成可复用内容表面，再在 GPU 中混合。颜色对照发现通用缩小 mip 会改变细节采样，已收紧可直接使用的条件；真实 PSD 对照最大差由 169 降至 1。CPU 和 GPU 采用一致的双线性采样规则。

GPU 纹理缓存最多 128 MiB、帧缓冲池最多 32 MiB；正在使用的浮点模糊表面可超过池上限。两者与原表面/Worker/撤销共用 512 MiB 软预算，后台文档优先回收。移除、版本变化、关闭和上下文丢失释放纹理；分配失败清理已创建的半成品。上下文恢复后重建程序及纹理。GPU 无法创建/渲染失败时返回 Canvas 路径。CMYK 校样、剪贴与需背景参与的复杂穿透组保留 Canvas/ICC 路径，完整保留原效果。

高斯和方框模糊在现有专用 Worker 内通过浮点 GPU 前缀和计算。`blurKernel` 将 CPU/GPU 的半径、轮数、影响范围统一；分块包含全部实际内核边缘后裁回核心。表面模糊或浮点 GPU 不支持时逐块调用原 CPU 内核。RGBA 预乘、垂直方向及最终量化已与原结果对照。图像以位图传给 Worker，滤镜各通道/轮次之间保留 GPU 浮点表面，预览取消释放位图。动感、径向和平均模糊仍采用原全局采样算法。

### 大图与导出

PNG 在现有后台队列的独立导出任务中，按效果/蒙版及祖先组影响范围预留边缘，跨块复用内容缓存；合成参数、像素网格和 ICC 与预览共用。编码使用 64 行暂存带、PNG Sub 行过滤及 `CompressionStream`，按 IDAT 流式压缩，避免新建整幅导出 RGBA Canvas。离屏目标的 style/dataset 兼容已补齐，画板临时项目即使导出失败也释放资源。

JPEG、PSD 合成也使用同一渲染入口，但编码仍需完整输出；分层 PSD 的转换与编码没有改成流式。PNG 最终压缩文件仍以 Blob/base64 交给宿主。源素材、已应用滤镜的最终像素 Canvas、最后一份撤销尚未分页化；保留 16384 单边限制。不能据此承诺任意尺寸/素材组合不会耗尽总内存。

## 实现范围

- 拖动按素材原位置、当前位置及效果影响范围重新合成，只更新变化区域；静止区域保留原像素。取消拖动恢复按下时的画面。
- 带样式/蒙版的普通图层使用包含效果边缘的局部表面。整数像素平移可复用效果缓存；子像素平移重新采样，避免重复插值。图案叠加仍按文档坐标处理。移动画板或涉及组效果时保留完整视口回退。
- 剪贴混合、组透明度、调整层和 CMYK 校样只读写需要重算的区域；临时合成表面复用，池上限 32 MiB。
- 调整层实时预览通过现有 Worker 计算。同一文档只保留最新排队请求，过期结果不显示；取消/切换/关闭会使旧任务失效。参数预览与清晰预览采用一致的可见范围和位图尺寸。
- 渲染表面、蒙版缓存、后台素材、清晰合成和撤销像素共用 512 MiB 软预算，先回收后台文档缓存。这个预算管理可回收资源，不包含全部源图、浏览器进程或 GPU 驱动内存；正在使用的资源及最后一个撤销记录可超出软预算。
- 像素撤销共享一份不可变基图，以 256×256 像素块记录后续变化。画笔/橡皮擦提供局部变化范围；无法确定范围的操作比较完整表面。撤销恢复后仍可编辑。内部 `_tiles` 不写入 `.ccomp`，公开文件格式仍为 v8。
- 关闭文档、撤销替换项目、图像尺寸替换会释放旧预览、后台素材和缓存登记；关闭最后一个文档会释放显示画布和当前项目引用。
