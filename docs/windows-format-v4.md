# Windows .ccomp v4 additions

The Windows manifest version is now 4. It is independent from macOS `.comp`; the macOS manifest and `ProjectManifest.current` are unchanged. The reader accepts Windows v1–v4. Versions below 4 cannot contain the new style or paragraph fields.

Optional `styles` maps effect names to parameter objects: `bevel`, `stroke`, `innerShadow`, `innerGlow`, `satin`, `colorOverlay`, `gradientOverlay`, `patternOverlay`, `outerGlow`, and `dropShadow`. Each has boolean `enabled`, 0–1 opacity, colors as six-digit RGB hex strings, and the applicable fields defined by `src/effect-model.mjs`. `stylesEnabled` controls global FX visibility. Optional `fillOpacity` is 0–1 and affects content separately from FX. Style size is 0–250 document pixels, distance 0–1000, angle ±360°, spread 0–100%, bevel depth 0–1000%, and altitude 0–90°. Contour and texture are bevel parameters. Pattern overlays use deterministic checker, stripe, or dot patterns. Style editing is non-destructive and participates in undo.

Text layers optionally have `textMode` (`point` or `paragraph`), `boxWidth` and `boxHeight` (1–16384 local pixels for paragraphs), `align` (left/center/right), `lineHeight` (0.5–5 multiples of font size), and `letterSpacing` (−100–1000 local pixels). Paragraph text wraps and clips to its box. `textRasterCache: true` together with a PNG `data` preserves imported PSD text appearance until its content or typography is edited; the bitmap counts toward the shared source-pixel budget. Optional `psdFont`, `psdTextSource`, and `textCacheOrigin` retain exchange metadata. PNG appearance caches are discarded on typography edits; editing can reflow with the installed font or its fallback.

`psdEffects` retains original PSD FX descriptors. When `stylesModified` is true, editable effects are regenerated on export. Common FX and simple horizontal text export with native PSD metadata and cached pixels. Procedural pattern overlays and textured/nonlinear-contour bevels are baked into individual pixel layers on PSD export; `.ccomp` retains all editable settings. Unsupported adjustments, vectors and advanced blending generate a conversion report but do not flatten the whole document. Composite-only opening remains an explicit separate choice.

Temporary render caches (`_surface`, `_bounds`), inline editing state, transform gestures and alignment guides are not saved. Uniform resize/rotation still use the existing `scale` and `rotation` fields. Group transforms update descendants and linked masks while group x/y/scale/rotation remain fixed.
