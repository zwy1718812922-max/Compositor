# Windows .ccomp v9: editable filters

The Windows port saves version 9 and reads versions 1–8. The independent macOS `.comp` format and `ProjectManifest.current` are unchanged.

A raster layer may contain `filters`, an array of up to 32 records in evaluation order. `data` continues to hold the original PNG, not the filtered output. Each filter stores a unique string `id`, `kind`, boolean `enabled`, finite `strength` (0–1), and `values`. Disabled filters and zero strength preserve source pixels. Filter state is included in undo snapshots. Render caches, worker bitmaps, presets and viewport state are not project fields.

Kinds are `gaussian`, `box`, `surface`, `motion`, `radial`, `average`, `usm`, `highpass`, `median`, `curves`, and `lut`. Numeric limits and defaults are defined in `windows/src/filter-model.mjs` and validated in both desktop hosts. Spatial radii use source pixels, independent of layer transform. Local filters reserve their complete dependency radius when composing source tiles; Gaussian, box and motion blur can extend outside source bounds. Filters currently operate on the entire raster source; the layer mask and layer effects are applied afterward.

Curves store `values.points`: optional `rgb`, `red`, `green`, `blue` channel arrays of `[input, output]`, each with 2–32 control points. Coordinates are finite in 0–255, inputs strictly increase, and the first/last inputs are 0/255. Missing channels are identity. RGB is evaluated before individual channels using piecewise linear interpolation. Adjustment layers of kind `curves` also support these points; legacy `amount` remains readable when points are absent.

A LUT stores `values.lut` with `name`, integer `size` (2–65), `min`/`max` three-component domains, and `data` with `size³×3` finite RGB samples, red index varying fastest. Sampling is trilinear. Standard 3D `.cube` files are accepted; 1D and combined tables are rejected. The embedded table makes a saved project independent of the imported file. Adjustment layers of kind `lookup` also support a table with their existing `amount` parameter.

Fit previews use a source pyramid with spatial parameters converted to that level. The 100% local preview and exports use full source resolution and the same filter pipeline. PNG export composes bounded output tiles. JPEG and PSD still require full output for encoding. Raster filter stacks are baked into PSD pixel layers, including blur padding; if padded bounds exceed the 16384 source limit, baking retains their visible document intersection. Their original sources and editable parameters remain available in `.ccomp`. RGB/channel curve adjustment descriptors and imported LUT adjustment descriptors are exported separately.

Pixel storage remains RGBA8/sRGB; this is not a 16-bit/HDR pipeline. Intermediate Canvas conversion can introduce small alpha quantization differences. Hardware GPU float kernels accelerate Gaussian/box blur and the blur stage of sharpening/high pass; software GPU, unsupported float buffers and context failures use CPU kernels. A stack containing USM with a positive hard threshold uses CPU kernels throughout so GPU rounding cannot change the threshold decision. Filter window display applies the same CMYK proof transform as the document after filtering. Source images remain full raster assets, but filter results and intermediate stages are cached as bounded tiles under the shared memory budget. Radial sampling rejects a single dependency window above 16 million pixels rather than allocating an unbounded buffer.

Last parameters, strength and user presets are stored in the application's IndexedDB settings, including LUT data. They survive restart without being limited to localStorage's small string quota. Project filter stacks remain separate from these defaults and do not depend on the settings database.
